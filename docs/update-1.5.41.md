# 1.5.41 使用与验收范围

基线是用户上传的 1.5.40-rulelimit1，保留该版本内容；不是用更早的测试包覆盖。

## 已增加的三个入口

1. 设置首页「母本库：导入与备份」→ 管理已导入母本库 → 在指定库点击「勾选参与抽签的条目」。取消勾选不删除原文，刷新仍保留，影响以后的抽签。换角色卡时可手动改选；本版不是自动保存多套角色卡配置。全局抽签和整库开关仍须开启。条目列表一次只展示一本库的一页；搜索由用户主动触发。
2. 打开对应镜面的维修兔菜单 →「复制本面 HTML（含样式）」。复制的是这一面，不包含整份诊断或其他楼层；粘贴为纯文本并保存为 `.html`。保留原生 HTML/CSS 交互与当前控件状态，依赖插件脚本的维修交互不会作为可执行脚本导出。自动复制不可用时提供手动复制框。
3. 高级设置 → 共同回忆资料来源 → 开启额外资料来源及记忆世界书来源 → 刷新世界书目录 → 选定一本。跟随与独立 API 只有实际抽中 I.1「共同回忆」才读取绑定书；只把成功读取、按预算选取的资料加入 Prompt。关闭来源保留绑定，清空绑定可解除。不会新增模型请求，但实际带入的资料会增加本次 Prompt Token。独立 API 不因此读取旧记忆插件接口。

目录按钮只请求书名目录，启动和开设置不读取正文。宿主读取接口按一本书返回内容，不是逐条服务器读取；本次内存中提取最多 24 个启用条目，并受最多 6000 字和共同回忆总预算约束，不缓存整书。超限按宿主条目顺序取部分资料，不能把它当成全部记忆。读取期间换聊天、改正文归属或改变相关绑定设置时，不使用过期结果。

## TT 虚化界面消失：尚未根治

当前核验的 TT 上游存在启动时序竞态：大部分第三方扩展延后加载，而 ChatSurface 在首次非空聊天投影后拒绝注册。兔子镜可能错过窗口，出现 managed=true / registered=false。源码及真实注册器测试已复现，但用户报告原本未保存具体异常，所以不能证明每次注册失败都只有此原因。

本版诊断区分 late-projection、duplicate-participant、host-rejected，只记录固定原因码，不保存异常正文。late-projection 需要 TT 提供投影前的 participant 加载阶段；改插件 loading_order、反复点开或同页切换虚化不能补注册，重启在相同宿主时序下也不保证解决。duplicate-participant 时先确认只启用一份正式/测试兔子镜，再重新打开应用。

没有关闭 DOM 虚化，没有接管宿主私有注册器，没有加入常驻轮询、全聊天扫描或强制展开历史。当前正式通道包不表示这个宿主阻塞已解决。维护者定位见 [TT 启动契约定位](tt-registration-1.5.41.md)。

## 安装

正式/测试 ZIP 的运行代码一致，仅 manifest 的名称、仓库和自动更新通道不同。选择一个使用，不同时启用两份；将包内 `RabbitMirror` 的内容覆盖原兔子镜扩展目录，不额外套目录。备份后更新并整页刷新以加载统一版本；不要清除聊天、站点数据、母本库或冷却记录。ZIP 交付没有推送仓库，也不替你改变原 Git 远程。

验证使用离线原创数据、宿主接口替身及真实浏览器 IndexedDB/DOM；没有调用付费模型、部署云酒馆或完成 TT/手机真机验收。完整证据保留在工作目录 verification；旧测试存在基线失败，不能声称全仓测试全部通过。
