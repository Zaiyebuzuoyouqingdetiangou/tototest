# 跨设备成品与维修：尚未完成的验收

2026-09-06。此文不表示功能已实现或真实两端已通过。

## 已核对的事实

- 旧 1.2.7 确实把独立成品追加到所属消息和当前 Swipe，并排队调用宿主聊天保存；另一个设备可从消息重新恢复。因此不能把用户此前能跨设备恢复的反馈当作误解。
- 当前主动保存被 ChatSafety 边界停用。独立成品更新本地存储和活的 chatMetadata；下一次宿主正常保存可能顺带持久化，但生成后立即换设备不保证恢复。
- 跟随模式的部分成功与补成功结果还使用本地 followPartialResults 账本。只处理独立 API 元数据不能覆盖这一路线。
- 不能把 `detail.persisted=true`（本地及内存回读）称为服务器确认，也不能直接调用整聊保存来绕过空载、半载和旧设备覆盖风险。
- 不能在没有实际云酒馆能力证据时，要求用户先安装服务端插件。应先核对宿主已有保存能力；标准上游源码不等于这家云酒馆的部署能力。

## 必须通过的实际验收

使用同一云酒馆账号、同一扩展版本和原创独立测试聊天，不清除用户现有站点数据或母本。测试表中的每行都需要实际证据；Node、桌面合成页、单机刷新均不替代。

| 方向 | 源端操作 | 接收端验收 | 状态 |
| --- | --- | --- | --- |
| 手机→电脑 | 生成完整单面及多面，等待明确保存结果，不再发送新聊天 | 打开相同聊天/Swipe，标题、各面内容、数量和归属一致，交互直接可用 | 待验收 |
| 手机→电脑 | 只维修其中一面并等待保存，不再发送新聊天 | 恢复目标面的维修结果，其他面未被替换 | 待验收 |
| 电脑→手机 | 生成完整单面及多面，等待明确保存结果，不再发送新聊天 | 同上；使用真实手机，不以桌面窄屏替代 | 待验收 |
| 电脑→手机 | 只维修其中一面并等待保存，不再发送新聊天 | 同上；重开聊天后仍保留 | 待验收 |
| 两个方向 | 跟随 API 部分成功、手动补失败面 | 成功面及补成功面均恢复，不自动补请求 | 待验收 |
| 旧设备返回 | A 保留旧页面，B 已产生新维修结果，再回到 A | A 不用旧快照覆盖 B 的结果；冲突必须可见且不丢成品 | 待验收 |

记录仅保留版本、测试用例标识、面数、归属摘要、成品/维修前后摘要和结果；不保存私人聊天、母本、Prompt、密钥或完整响应。旧手机缓存是可能仅存的成品副本，在确认云端恢复前必须保留。

## 与本次交互修复的区别

首次打开绑定缺失、维修保存消息序号缺失是本地运行时缺陷；修复它们并通过离线回归，只说明对应调用链恢复。跨设备仍需要真正的云端写入、读回和上述两端测试，不能合并宣称完成。
