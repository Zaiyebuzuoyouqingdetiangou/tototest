# 多面兔子镜第二阶段设计（未实现）

状态：仅设计。本文不代表已经支持一次响应输出多面、batch DOM、分面维修或分面 Touch Theater。本轮第一阶段只涉及设置、批次随机计划及 pending/history 基础；不得从本文直接推断这些设计已接入生产。

证据基线：本轮解压的 `rabbitmirror-abc/baseline/tototest-main`。下列代码行号指该只读基线，不以旧 multiface 包、版本名或说明文件代替实际源码。本设计没有运行真实 SillyTavern、模型、网络或手机测试。

## 1. 结论与阶段边界

推荐第二阶段采用“一个协议 `<toto>` 包含多个独立 face”及“一个可信 batch host 包含多个局部 face 根”。协议外壳不等于固定 UI 外壳：不能把它做成固定三卡、固定页签、固定一列三块或固定 Face 1/2/3 标题条。

仍按 2A / 2B 拆分：

- 2A：一次响应、多面协议、受限边界解析、逐面净化、整批身份、batch 数据与错误分类。只在明确的测试/显式开发入口验证，不把未完成的多面结果交给现有单面挂载器。
- 2B：可信 batch host、历史恢复、局部工具与交互、视觉扫描、手机布局、几何和 `.mes` 替换恢复。全部身份/性能门槛通过后才开放产品生成入口。

`faceCount=1` 始终走旧生产分支，不加载多面协议/渲染模块，不新增 batch 标记、Prompt 字符、请求、历史迁移或 DOM。

### 1.1 C1 新确认的实现边界及 C2 前置门槛

本节补充依据本轮候选包 `rabbitmirror-abc/candidate/RabbitMirror` 的实际源码；本节行号指该候选快照，不替代其余章节注明的原 ZIP 基线。C1 当前只提供规划/存储基础，`pickCombinationBatch` 尚未接入实际生成调用链；以下 C2 门槛都是后续待实现、待验收的要求，不是当前已有能力。

1. **soft-pity 只读规划，不是成功计数闭环。** `picker.js:889–907,910–938,1011–1037` 的纯多面规划路径只快照读取已有 `formatEligibleMisses`，各面使用相同既有 soft-pity 倍率；不执行全局 eligible aging，也不 reset 命中项。`storage.js:840–877,925` 的显式分面 commit 写历史/提交标记，同样不更新 pity。降为原单面时的 `picker.js:941–954` 仍沿用单面原有 aging/reset/attempt 顺序，不应把它描述成纯多面规划的副作用。C2 接生成前必须单独定义：一次真实批次最多一次 eligible aging，以及由仍属当前 owner 的真实成功面触发 reset；不能在规划、逐面循环、读取缓存、历史回放或重复 commit 时累计，也不能因有 2/3 面而让全局未命中计数增加 2/3 次。部分成功只允许实际成功面的命中项 reset，失败/取消/迟到面不冒充成功；如何与原单面 attempt 语义兼容须显式审定，不借本轮 C1 偷改旧路径。

2. **有界单槽，不是多个在途 owner 的 registry。** 当前 `picker.js:808,999–1003,1036` 只有一个 `cachedBatchPlan`，`storage.js:664,767–780,804–837` 也只保存一个 pending batch 槽。连续读取同一 owner/设置身份且 pending 仍匹配时计划稳定；交错读取另一 scope、写入另一批或发生槽位淘汰后，不保证旧缓存/旧 pending 仍在。不能将这种连续读取幂等性宣称为跨多个同时在途消息的稳定性。C2 若支持并行消息，必须为每个完整 owner/operation 建立独立且有明确容量上限的生命周期记录，定义 active/terminal、取消、销毁、容量不足、迟到及回放行为；付费 lease 已消费这一事实不能随缓存淘汰而被忘记，淘汰不得授权重抽或重新发送。不能仅靠一个全局 `const` 对象或最后一次计划变量声称实现了 owner 隔离，也不能用无界 Map 或新增常驻轮询替代容量/清理规则。

3. **同 owner 的显式点菜/禁用变化必须使旧计划失效。** `picker.js:829–879` 的身份白名单包含当前解析后的 `rawDirective/disabled/themeIds/formatIds`；即使 chat、mesid、swipe、sourceHash 不变，用户明确点菜或禁用发生变化也不能沿用旧计划。当前流程只在一次规划入口读取一次既有当前轮用户消息并解析，将同一 directive 快照传到 `batchPickSnapshot` 和后续面，不按面重新读取或全聊天扫描。C2 必须把这项失效条件接到真实 operation 身份/取消终检：发送前使旧计划不可用，已发送时拒绝把旧结果当成新指令结果，且不会因此自动补请求。指纹只含有界的明确指令/设置，不保存整条聊天正文；不能用反复全聊天扫描或周期检查来维持一致性。

## 2. 当前结构为何不能直接接多个输出

C1 受控模拟还确认：现有正式冷却窗口按成功 face 条目计数，而非 batch 轮数。默认最近 10 条时，1/2/3 面 exact 最短轮距分别为 11/6/4；batch 内 exact 排除仍严格成立。C2 必须明确采用“最近成功面”还是“最近生成批次”的单位，报告总窗口和部分成功含义；未经单独审定不能将历史扩容或计数规则变化混入本轮，更不能把该模拟描述为多面仍有 10 整轮保护。

| 基线证据 | 当前行为 | 对第二阶段的约束 |
| --- | --- | --- |
| `src/promptBuilder.js:271–281,648–683,686–762` | 输出协议和独立近输出锁都要求唯一成品 | 多面分支必须同步切换有关“唯一成品”的协议语义；不能同时发送互相矛盾的单面/多面锁 |

## 3. 输出协议比较与推荐

| 维度 | 多个平级 `<toto>` | 一个 `<toto>` 内含多个 face |
| --- | --- | --- |
| 单面片段复用 | 每面外壳接近现状，单面净化容易复用 | 提取 face 后在离线局部模板包装为旧单面输入，同样可复用 |
| 解析风险 | 主回复中历史/额外 `<toto>` 混入时需更强批次边界；当前首/末选择分歧明显 | 一个明确外边界；仍须检查内部 face 数量及嵌套，不依赖正则 |
| 部分完成 | 可保留已闭合的平级片段 | 可保留已证明完整的 face；外边界截断时须丢弃共享布局并使用本地恢复显示 |
| 随机多面组织 | 仅平级独立块不便表达内容驱动的整体阅读路径，另需布局协议 | 可以有安全的共享结构及局部 face，容易保留非固定组织方式 |
| 现有不发送正则 | 可能匹配多段，但不能用该正则承担身份验证 | 维持一个外部 `<toto>` 范围；仍需验证宿主标签隔离路径 |
| 历史与外置 host | 需额外聚合哪些片段属于同一批 | 自然映射为一条 batch 记录和一个 owner host |

推荐单 envelope，不允许 `<toto>` 嵌套。示意协议（不是已实现接口，也不是固定布局模板）：

```html
<toto data-rabbit-mirror="true">
  <!-- 这里只是文档标注；实际输出仍禁止 HTML 注释。 -->
  <rm-face ref="本次计划的无权限引用"><details>…该面完整内容…</details></rm-face>
  <rm-face ref="另一个无权限引用"><details>…另一面完整内容…</details></rm-face>
</toto>
```

`rm-face/ref` 只是一种拟议的线协议，不能原样挂载。解析器验证后丢弃它们，本地再创建可信局部根；最终标签名和字段名由 2A 小型协议测试冻结。共享布局如需提供，只能在本批次 envelope 内声明，不得将任一 face 的内容放到自己边界外。

### 3.1 计划与身份绑定

本地冻结一次 batch plan，包含：`batchId`、完整 owner（chat、mesid、swipe、sourceHash、revision/operation epoch）、generation scope、生成相关设置指纹、有序 faces。每个 face 的 `faceIndex/themeIds/formatIds` 只来自该计划。

模型只收到每面所需的主题/形式说明，以及一个本次请求内有效的无权限 `ref`。该引用不是 batchId、faceIndex、owner 或缓存键，不能授权请求、维修、历史写入或 DOM 回绑。随机引用如需创建，应使用与 picker 随机流分离的可信标识生成器，不能消耗 picker 的随机数。

返回引用必须属于当前冻结计划；未知、重复、缺失都进入明确错误状态。收到的顺序可以不同，最终按可信 `faceIndex` 排序。模型即使输出 batchId、faceIndex、mesid、owner、sourceHash、内部缓存字段，也一律忽略并删除；不得合并进入运行时对象。不能因为“引用匹配”就宣称模型内容一定兑现了主题/形式。

### 3.2 不同切面的 Prompt

全局输出安全、兔子洞、视觉质量、可见中文、冷却及增强视觉许可只写一次；额外 faces 只增加自己的选择材料和简短差异约束。不把整套基础 Prompt 复制 N 次，不为 face 重新调用模型。

多面分支要求每面独立兑现其主题/形式及观察角度，不复制第一面文本，不只换标题/配色，不将几面计划折中成一个通用信息板。不得强制分配“论坛+信件+游戏”之类固定职责，也不新增布局 picker。SVG 是可选媒介，不成为 batch 或任一 face 的必要条件。

重复判断分两层：相同安全正文/结构指纹可确认为明显复制并将重复 face 标为本地质量失败；“角度是否真正不同、形式是否落实”需保留逐面计划证据并做真实模型人工验收，不能靠标题、颜色、ref 或字符串存在假装证明。质量不合格不会自动补请求。

### 3.3 Prompt 预算预估

基线 `promptBuilder.js:21–25` 每组已选母本补充的预算为 compact 0、balanced 主题360+形式540、full 主题900+形式1500 字符；另有每项170/210字符摘要及ID、标题、标签、执行说明。不能为了让多面塞得下，悄悄压缩这些单面质量规则。

一个示意共享协议正文约281字符，连接分隔符后283字符；这是文案计算，不是生产 Prompt 测试。再为每个 face 增加计划引用/说明，并增加额外 face 的现有格式化选材。预计相对单面（不是总请求大小）：

| rawPolicy | 2面预计新增字符 | 3面预计新增字符 | 估算 Token 说明 |
| --- | ---: | ---: | --- |
| compact | 约700–1,700 | 约1,100–3,100 | 不新增母本原文补充；中文占比高时约为新增字符的0.7–0.9倍 |
| balanced | 约1,100–2,600 | 约1,900–4,900 | 按每面原摘要和母本预算，绝不复制全局规则 |
| full | 约2,100–4,100 | 约3,900–7,900 | 超出完整请求余量时须请求前失败，不能截掉核心规则或偷发第二次 |

这些是方案级区间而非保证值，主题/形式数量、标题和真实母本长度会改变结果。对应中性估算约 compact 2面490–1,530 / 3面770–2,790；balanced 2面770–2,340 / 3面1,330–4,410；full 2面1,470–3,690 / 3面2,730–7,110 Token。2A 必须直接对最终真实字符串调用现有 `estimatePromptTokens`，报告总量及增量；不是模型官方 tokenizer 的精确 Token。

独立请求仍受原12,000聊天正文、20,000上下文、32,000完整请求字符上限约束。额外计划可能挤占上下文，必须在诊断里如实显示；不足时只能在网络发送前失败或由用户调整设置，不自动换模型、增预算、降为多请求。`faceCount=1` 增量严格为0。

## 4. 一次响应的安全解析和部分成功

新增一个受限、无DOM、无网络的批次边界解析器，按字符推进并跟踪标签、成对引号、注释/CDATA、style原文区域和层级。限制总字符、token/标签数量和深度；每个输入位置只有限次处理。不能用一个非贪婪正则切所有 face，也不能让浏览器自动修补的 DOM 来证明源文本闭合。

顺序：已有单响应读取 → 总响应预算 → 批次词法边界 → 按计划映射 face → 每面结构/预算 → 每面离线净化 → 每面质量判定 → 整批 owner 最终复核 → 一次提交安全结果。

| 异常 | 处理 |
| --- | --- |
| 缺少 face | 已完整且安全的面可保留；缺面为本地错误槽，不请求补齐 |
| 同 ref 重复 | 不采用“最后一个覆盖”；该槽冲突失败，其余已证明独立的槽可保留 |
| 顺序不同 | 按可信计划排序，不把返回顺序当 faceIndex |
| 未知 ref/额外面 | 不进入正式内容或历史；若无法证明边界独立，整批拒绝 |
| 某面标签/CSS不闭合 | 该面失败，不能由DOM自动补全后冒充完整 |
| 某面缺有效 details/summary/正文 | 该面质量失败，不以一段文字占位冒充成品 |
| 第二/第三面截断 | 只可使用截断前已独立闭合、预算合格的面；未闭合部分不送DOM，不挂载 |
| envelope结尾缺失 | 仅当解析器已证明前缀face边界完整才允许局部保留；共享布局一律丢弃，以本地可达恢复视图展示 |
| 嵌套toto/跨face闭合/共享style边界污染 | 身份或词法边界不再可信，整批拒绝 |
| 全批/全局预算超限 | 整批拒绝，不通过拆分规避原总响应上限 |
| 用户停止、owner已变、迟到结果 | 整批终止，不将已过期的安全face回绑到新正文 |

仅在响应结束（含已确定的协议终止或可分类的传输结束）后一次提交，不逐token挂载。部分成功不等于自动恢复请求：失败槽只提供说明和用户主动的整批重新生成入口。明确显示此次重新生成是新的用户请求并可能计费；不能在后台自动补第2/3面。

## 5. 每面净化和身份/交互隔离

每面独立调用同一现有安全入口，不新增“增强SVG宽松通道”，不修改允许集合。先验证整批总预算，再验证每面预算；不能把4200节点上限简单乘以3，绕过原总复杂度保护。2A 应在现有总上限内分配可借用的局部剩余额度，不强求每面完全平均；超限时明确本地失败。

必须隔离以下全部路径：

- HTML id及其CSS选择器、本地锚点、label/for、aria-controls/labelledby/describedby。
- radio name、checked状态、局部popover/command目标、维修/交互恢复目标。
- SVG gradient/mask/clipPath/filter id、`url(#id)`、href/xlink:href、SMIL begin/end引用。
- class、keyframe、CSS变量及可穿透局部根的选择器；仅给id加前缀还不够。

命名空间由本地 `batchId + faceIndex + 稳定局部前缀` 派生，稳定回载且不双重加前缀。调用现有 `isolateRabbitMirrorInteractionIds` 的局部根，不在整批合并DOM上先生成一份共享映射。`outputSanitizer.js:11469–11521,11883–11926` 已有多类本地引用处理，但 2A/2B 仍须负例证明它不会跨 face 命中；不得从现有函数名推断全覆盖。

共享布局与内容样式分层：共享布局只可作用于该批次可信face外框/阅读路径，不能选择或读写任一面内部控件；各face样式仅可作用于自己的局部根。模型可提供布局意图/安全结构，但本地必须重写范围并验证可达性，不能允许CSS选择宿主聊天、工具按钮或另一batch。没有安全布局时可以进入有明确“局部恢复”说明的可达回退视图；回退不能成为所有正常作品的固定模板。

### 5.1 必须在第二阶段启用前解决的既有安全预期差异

基线直接内联SVG不是完整标签白名单：`outputSanitizer.js:16748`禁止selector未含foreignObject，16817仅拒绝数据SVG中的foreignObject。17251–17300也没有系统清除所有模型伪造owner/data命名空间；外层可信host在`independentApi.js:3488–3514`重盖身份，不代表每个内部属性都可信。

以上是源码确认的策略差异，不是本设计已复现的攻击。不能在本文承诺“现有净化器已拒绝所有foreignObject/所有内部属性”，也不能趁本轮更改sanitizer。第二阶段上线前要用实际入口负例验证并单独审定最小安全修复；若安全多面只能靠放宽集合或信任模型属性实现，停止该项。

现有合法能力损失也需告知：外部SVG use/image/font依赖、事件/脚本、数据SVG中的foreignObject及超复杂矢量会被删除或拒绝；基础形状、本地渐变/裁切/蒙版可在既有策略内使用。固定塔罗牌图白名单是现存特例，不将其扩展成任意网络素材。

## 6. 一个batch host与多个host的比较

| 维度 | 一个batch host（推荐） | 多face host |
| --- | --- | --- |
| `.mes`暂移除/重插 | 一次标记awaiting-owner，一次精确重挂 | 必须聚合全部host，否则只恢复一部分 |
| Swipe/sourceHash变化 | 一个owner整批失效 | 每host独立失效容易残留旧面 |
| 旧面回绑 | 所有面需通过同一batch owner gate | 某面可能单独走旧单面alias恢复 |
| 历史 | 一个batch record，faces固定按index排序 | 需要额外索引把零散历史聚合为完整批 |
| 维修兔 | 一个批次入口选择目标face，局部操作 | 每host重复工具，界面容易膨胀 |
| 视觉扫描 | 一批调度、每面一次局部分析 | 容易重复现有全局两次settled扫描 |
| Touch Theater | 以明确face根绑定，状态局部存储 | 也需face身份，不能只靠mesid |
| 手机布局 | 一个外层宽度边界，内容组织不固定 | 多个宽度和定位过程彼此干扰风险更大 |
| 几何/小米外置宽度 | 共享既有宿主内容车道和一个周期 | 现有每host几何过程可能乘2/3 |
| DOM节点 | 一个外壳+N局部根/实际内容 | N外壳+N工具/边界+实际内容 |
| 性能 | 索引/提交/挂载批处理，局部内容O(sum nodes) | 去重、扫描、保存、settle容易按N重复 |
| 局部失败/重绘 | 替换单face根，batch身份不变 | 本身也能局部，但要避免被既有去重删除 |
| ID/CSS隔离 | 必须逐面命名空间 | 仍然必须；多host本身不是隔离机制 |

可信host只能由插件创建。模型输出不得持有真实host的控制属性、aria-live状态或工具节点。batch host维持一个`ready/partial/error/loading`批状态；faces各自有不可变身份和局部状态。状态改变不是重新抽签或新请求的授权。

## 7. 跟随API/独立API一次请求链

跟随当前API继续在`injector.js:389–414`一次setExtensionPrompt加入本轮多面协议；不额外调用独立API，不按face调用主模型。主回复完成后从同一次响应中解析该批，用户正文不因face失败被删除或重写。

独立API保留：

- `independentApi.js:292–322` dispatch lease，自动按baseSlot/epoch消费一次，用户明确重说才创建新lease。
- `1008–1011,1091–1115` chat/mesid/swipe/body sourceHash身份与revision。
- `2294–2462`同一个Response的SSE/NDJSON/非流式解析，不把DeepSeek reasoning/thought字段提升为成品。
- `6579–6810`一个flight、一个AbortController、当前owner终检、成功后一次整批挂载。

保留当前对“宿主展示改写”和“显式正文替换”的区别，不在第一阶段或第二阶段附带重写这套判定。batch只把可信批次ID/计划指纹挂到现有flight对象及提交条件上。任何face迟到、取消或重放都不能绕过整批终检；按face复制generateFor/callIndependentApi属于方案失败。

## 8. 历史、pending和缓存契约

单面历史维持现有格式和key，不迁成batch，不给旧记录补faceIndex=0。多面使用带明确kind/version的新记录；阶段1已有基础接口可等价复用，但第二阶段内容记录必须与单面兼容入口区分。

建议数据形状（设计字段，未实现）：

```text
BatchRecord {
  kind: "multiface", schemaVersion,
  batchId, generationScope, owner: {chat, mesid, swipe, sourceHash, revision, epoch},
  generationSettingsHash, requestedFaceCount, status,
  faces: [{faceIndex, themeIds, formatIds, status, html, initialHtml, resultHash, errorCode}],
  requestDiagnostic, createdAt, completedAt
}
```

所有身份字段由本地冻结计划赋值；HTML是经过净化和局部隔离的结果，不持久保存未净化输出或本轮目标正文缓存。faces持久化按faceIndex排序，不能以网络到达顺序作为历史顺序。

幂等键使用`batchId + faceIndex`，并验证owner和结果哈希。同一身份、同一结果再次提交为no-op；同一身份不同结果不能“后到覆盖”，应拒绝/记录冲突。所有已接受face在同一次批次提交事务中进入历史；不得因遍历face多次重复写全局冷却历史。第一阶段既定attempt/success语义不能借第二阶段偷偷改写。

新batch pending建立必须明确只清理同一owner/generation scope的旧单面pending；不能清理其他聊天。写入后读回核对schema、身份、数量和hash，再缓存有效plan；不能留半成品plan。

| 事件 | pending/flight | 已完成历史/显示 | 请求行为 |
| --- | --- | --- | --- |
| 页面刷新 | 未完成标为中断；无有效flight不得自动恢复发送 | 完成batch按owner恢复，未完成槽本地说明 | 不因refresh补请求 |
| 聊天切换 | 当前批次整批取消/失去可提交资格 | 旧聊天历史保留，不在新聊天挂载 | 新聊天不得继承旧lease/正文 |
| 消息删除 | 该owner pending失效，销毁局部索引 | 历史按既定保留策略处理，但不得回绑其他mesid | 0次自动补请求 |
| Swipe/重说/正文明确替换 | 整批旧身份失效，清理全部局部根 | 旧记录只属于旧owner，不转移face | 仅新的明确生成操作可拥有新lease |
| 生成相关设置变化 | 冻结的settings指纹失配，整批失效 | 保留历史快照，不把旧face拼进新计划 | 无自动重试；展示位置切换只移动可信host |
| 用户停止 | 整批abort；迟到回调终检拒绝 | 保留停止前的旧成功成品，不能冒充本轮新成功 | 0次补请求 |
| 部分响应失败 | 标明partial/error并结束当前lease | 仅保留已证明安全完整且仍属当前owner的面 | 缺面不请求 |
| localStorage在发送前失败 | 不缓存半plan；第一阶段按其已审定规则安全单面回退 | 不写损坏pending | 第二阶段必须在付费发送前决定失败/回退，不能发送后补单面 |
| localStorage在发送后失败 | flight内标记本次已消费，禁止恢复逻辑重发 | 可显示已验证内存结果并明确“未持久保存”；已知旧成功记录不删 | 不因保存失败补请求 |

chatMetadata应一次聚合保存batch，不按面各保存一次全聊天。失败提示必须区分“模型/网络失败”和“生成成功但存储失败”。不能承诺未成功持久化的数据跨刷新仍可恢复。

当前目标可见正文继续在请求前新读并复核，小型正文缓存只归该生成调用所有；batch计划/历史只保存指纹，不跨轮缓存目标正文。

本节关于多个 owner 的清理、回放和聚合事务均是 C2 目标，不代表 C1 单槽已满足。C2 必须显式覆盖 A → B → A 的交错规划、同 owner 新指令、槽位淘汰、存储读回失败以及取消后的迟到提交；若尚无独立有界生命周期实现，应明确限制为一个多面批次在途并在发送前处理容量冲突，不能默默覆盖另一在途批次后承诺仍可恢复。记录容量应同时约束条目数和总大小，终结/取消即按规则回收，清理不依赖新增常驻定时器；回放只恢复已证明的结果，绝不恢复发送授权。

## 9. 手机、工具和随机展示

batch host只限定安全的宿主内容边界，不指定统一的视觉比例、配色、三卡、页签或纵列。作品可随内容形成章节、展览、多窗口、翻页、自然展开等安全结构，这些不是新picker分类或必须选一种的固定清单。

用户必须能通过可见、可触摸且可键盘操作的路径到达每个成功face及每个错误状态。不得仅靠hover或拖拽；有翻页/叠放时须有等价点击操作和明确返回路径。工具仍用原有兔子/反馈入口，不增一排重复图标；在现有菜单中选择“当前面/整批”作用域，确认后只操作目标局部根。

需验证360/375/390px及安卓小米实际WebView：无横向溢出、第二第三面不会被固定高度裁掉、长正文可扩展、安全区和输入栏不遮挡关闭/维修/反馈/重说。宿主全局字体和面板宽度变化不能重触发模型。focused control不被自建浮层遮挡；保留焦点轮廓与可读label，错误不只依赖颜色。该可达性要求来自UI/UX Pro Max定向查询，不表示采用该技能的固定风格或SVG图标建议。

几何读取集中在batch外层一次后绘制周期；逐面局部测量仅针对打开/操作的face。未展开的SVG/交互不启动重型救援扫描、永久监听或预渲染任务；安全CSS动画仍按既有边界，不能通过动态扩大DOM预算实现“更丰富”。

## 13. 停止条件与交付措辞

出现新增付费请求/自动重试、旧Swipe/sourceHash回绑、单面字节/行为变化、为了支持SVG放宽净化、全聊天工作乘面数、每面常驻Observer/轮询、宽度保护失败或缓存闭包不一致，应停在最小失败分支，不删测试、不以换模板掩盖。

第二阶段最大串面风险：模型伪造身份或旧单面恢复函数只凭mesid/标题把一个旧face挂入新batch。最大性能风险：将完整净化/扫描/工具/几何/存储链按面数复制，而非受限的局部内容工作。

本文件的方案、预算与拟议文件名均尚未实现。没有真实环境时统一说明：仅完成源码、自动化测试与随机分布模拟验证，尚未完成真实 SillyTavern、真实模型网络及手机实机验证。对于本第二阶段更应明确：目前仅完成源码依据与架构设计，尚未执行第二阶段自动化或实机验收。
