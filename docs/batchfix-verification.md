# 1.5.22 BatchFix1 验证范围

日期：2026-09-06。只修复基于 1.5.21 的外部母本连续多面规划失败。没有调用付费模型，没有读取用户母本正文，没有部署酒馆或 GitHub。

## 根因及红绿证据

原创 45 条外部母本（22 个主题、23 个展现），每轮五面、每面两个主题和两个展现。在同一聊天中保留上一轮尝试记录并完成释放：原 1.5.21 前两轮成功，第三轮稳定抛出 `MULTIFACE_PLAN_UNAVAILABLE`，`reasonCode=BATCH_SELECTION_INCOMPLETE`。这不是服务商网络失败；模型请求尚未发送。

`picker.js` 将历史尝试和同批排除一起传入外部采样的硬排除参数，导致历史记录排空可用池。失败不会推进该历史，因而可以持续拒绝。内置采样原有的历史避让已具备候选不足时回退机制，外部采样缺失对应语义。

修复将两种约束分开：外部历史仅优先避让；用户明确排除和当前批次已选 ID 永远不回用。只改变本次抽取的候选优先级，不增加二次抽签、计划、登记或请求，不清空缓存或历史。功能改动仅在 `src/picker.js` 和 `src/externalWorldBook/externalPool.js`。

## 新增回归

`tests/multifaceExternalCooldownRecovery.test.mjs` 共五项：

1. 原创 45 条经真实规范化、分类、存储、池、规划和渲染，连续八轮五面。每轮 10 个主题、10 个展现唯一；有新候选时优先避开前轮；登记幂等且正常释放。不重置前轮记录。
2. 历史覆盖全池时仍排除显式禁用 ID；五面内部不重复。
3. 真正不足的外部库仍在登记前拒绝，不偷偷使用内置库补齐。
4. 关闭普通避重时，历史尝试仍作为优先级；硬排除参数维持严格行为，全部硬排除返回空集。
5. 执行真实独立 API preflight、真实规划／渲染／登记／消费，八轮分别只到达一次模拟传输边界；宿主、DOM、raw 查找和网络使用替身。计数为 plan/render/raw/mark/consume/transport 各 8，没有网络请求。这验证程序路径，不代表服务商或手机真实生成通过。

修复前第一项第三轮失败，修复后五项通过。连同原有外部池、独立预取、多面登记、长 ID、批次规划及抽取多样性检查，共 56 项通过、0 失败。封包再执行全量测试和全新解压复测，最终数量及 ZIP SHA-256 以随包交付核验记录为准。

- 1.5.21 交互与本地维修功能保留；新版本缓存闭包整体换到 `1.5.22-batchfix1`。未修改安全净化、视觉 Prompt、输出额度、任务注册表容量或归属校验。
- 用户旧截图的泛化提示同时覆盖“计划失效／容量”等分支。本次只证明并修复上述连续抽取故障，不能由此断言手机上的所有分支已消失。没有要求用户额外付费重试。
- 用户提供的外部诊断包含 332ms／499ms 的 click processing，但未记录发送或维修点击，且不采集内部状态；它不能定位本次计划失败，也不能排除手机热或十几秒延迟。
- 成品及维修结果跨设备保存仍未完成，手机→电脑及电脑→手机的真实恢复验收继续按 `crossdevice-acceptance-pending.md`，不得用本地刷新、模拟数据或下一条聊天顺带保存替代。
