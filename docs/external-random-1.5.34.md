# 1.5.34 外部抽签与塔罗意图

基于保留的 1.5.33。仅 `promptBuilder.js`、`picker.js`、`externalWorldBook/externalPool.js` 有功能差异；其他运行文件仅更新缓存/版本。

## 本次修复

- 保留成品展示、美化文本、样式和交互要求。旧失败卡的预览兼容没有新增变化，也没有重新引入审美拦截。
- 塔罗规则依据选中条目明确的媒介/题材启用，不因否定、可选示例、叙事提及、通用规则或来源关键词而强加。确切内置塔罗格式继续生效；不删除或更改母本。
- 外部候选仍优先非近期、未尝试项。必须回退到近期候选时，以已有抽中次数降低高频项机会，库与库内两层均应用这一偏好。所有候选仍可抽中，不是固定轮播，不产生额外抽签/请求。
- 既有正式及尝试历史按最大次数合并，避免双计。只用已经读取的 ID 统计，没有新增存储、settings 体积、数据库迁移、整库原文读取或启动扫描。
- 关闭外部抽签、关闭避重复、没有历史、命中次数全部相同时，保留各自原有随机行为；同批硬排除不被回退恢复。

## 验证与限制

原创离线回归通过实际 planner/render 与 storage/picker/pool 路径，覆盖两种 API、混合多面、正反塔罗意图、冷却耗尽、跨库权重及连续五面。新测试先在旧实现失败，再验证修复。完整运行结果以开发交付目录的 `verification-result.json` 为准。

没有加载用户世界书、运行付费模型或部署在线酒馆。此修复不等于证明截图中每次塔罗都由同一原因导致；真实模型、iPhone/安卓观感与温升仍待验收。

精确条目不同但内容同类的语义去重未实现。外部元数据没有可靠的统一题材标签，不能凭标题猜测并批量剔除作者内容。候选太少、多个条目同类或模型偏好仍可能让结果相似。

原历史窗口按条目记录而非整批计算：例如五面每面一条记录时，十条窗口约覆盖两批；本次没有借修复改变内置与外部共用的窗口含义。
