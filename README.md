当前版本：**1.5.42**。修复 TT 触摸展开后延迟 mouse click 再次收起；增加不依赖虚化聊天挂载的轻量设置入口，点击才加载完整设置。正式与测试包运行代码一致，名称和更新通道以 manifest 为准。**TT managed 模式的晚注册阻塞尚未根治**，设置能打开不代表聊天已接入；不要求关闭虚化。详见 [本次修复与边界](docs/update-1.5.42.md) 和 [TT 维护者定位](docs/tt-registration-1.5.41.md)。仅源码与离线自动化验证，尚未真机或模型验收。

既有入口保持不变：补充创作规则位于「高级设置 → 独立 API」；设置首页「母本库：导入与备份」支持粘贴文字、导入 TXT/MD/JSON 或整库换设备。新手指引同步入口；生成与恢复链路不再调用审美拒收检查，真正失败按实际原因提示。详见 [此前入口说明](docs/update-1.5.38.md)。

本次补充同一次 API 响应的传输诊断；减少重复初始化；接入 TT 的消息挂载生命周期；改善一类本地事务瞬时占用造成的配额失败。新增默认关闭的“参考外观与交互”：仅提取有界结构摘要，不执行导入 HTML，不使用原故事正文。入口位于高级设置的“个性化视觉提示词”内。

外部条目仅随口提到、否定或举例塔罗时，不再强加塔罗专用规则。开启避重复后，仍优先未抽过的条目；候选都在冷却时，降低最近频繁抽中条目的机会，保留随机与多面排重。不读取整库、不新增设置存储，不用重新导入世界书。不同条目本身玩法相近、可抽条目太少或模型偏好，仍可能造成观感重复。

生成后不再因为三标签、版式普通、交互较简单、缺少牌图或视觉样式不足而丢弃已有内容；安全净化和结构检查仍保留。避免万能三标签的生成规则继续生效，但不能保证模型每次都遵守。旧失败卡只有在预览缓存仍可用时才能查看，点击后直接展开作品；已失效的缓存不能凭空恢复。

## 安装与更新

安装通道以包内 manifest 为准。正式仓库为：

```text
https://github.com/Zaiyebuzuoyouqingdetiangou/toto
```

测试仓库为 `https://github.com/Zaiyebuzuoyouqingdetiangou/tototest`。已有安装请保持原安装目录。更新前备份扩展与聊天；更新后重启 TT 或整页刷新，确认版本为 1.5.42。此安装包的交付不代表已经上传仓库；不要清除站点数据、母本、抽签记录或旧设备缓存。

ZIP 安装：使用“RabbitMirror-1.5.42.zip”或“RabbitMirror-1.5.42-test.zip”之一，将 `RabbitMirror` 内的文件和子文件夹整体放入原扩展目录，不要再套一层目录，也不要同时启用两份兔子镜。安装包不含 tests、scripts、package.json、私人聊天或用户模板；旧包和开发文件仍保留。

正式包 manifest 自动更新标记开启、主页为正式仓库；测试包关闭自动更新标记、主页为测试仓库。本地 ZIP 交付不等于已发布到远程。内置更新按钮仍更新当前安装目录所对应的仓库，不会因为主页字段或覆盖 ZIP 替你切换 Git 远程。如果原来装的是测试仓库，覆盖正式 ZIP 后仍可能从原测试仓库更新；本次不自动迁移、重装或更改远程地址。

设置顶部提供“检查并更新”：每次点击都直接请求宿主检查当前安装仓库，不依赖扩展管理页的按钮状态。成功后由你手动刷新；权限不足、非 Git 解压安装、宿主不支持接口或仓库网络故障时不能强行更新，也不会删除重装。此按钮不是 Git 强制重置。

“新手指引”默认折叠，首次打开才加载。分别提供跟随正文 API 与独立 API 流程，均先开启自动注入；独立流程包含连接、模型、读取层数与标签过滤。切换帮助页不会切换真实生成模式。

功能说明分六类、44 项，另有醒目的文字导入、文件导入与整库换设备快捷指引。点击名称只定位设置，并可返回原阅读位置。重说、维修等需要选择具体镜面的工具只说明入口；查看指引不会替你导入、开启抽签、执行更新或保存设置。

最低宿主版本标识为 1.13.0；连接配置复用使用的 Connection Manager 接口要求 1.18.0 或以上，旧宿主可使用手动配置的兼容独立接口。不同云酒馆和移动浏览器仍可能存在兼容差异。

## 主要功能

- 普通单面或 2～5 面生成，每面有独立标题、内容、交互和维修入口。
- 跟随正文 API 或独立 API，内嵌和外置显示设置。
- 增强视觉绘制、动态视觉、个性化视觉提示词。
- 纯文字粘贴、TXT / MD / JSON／酒馆世界书母本导入、分类管理、按需抽取与整库导出／导入。
- 🚫 禁词与文字替换：处理兔子镜可见文字，不额外加入模型 Prompt。
- 维修兔、本地交互恢复、挨打猫反馈、收藏和黑名单。

多面共用一次生成请求，但增加面数可能增加输出长度、耗时和费用。失败不自动补请求；合格面保留，失败面可手动重试。维修只处理已有内容，不能补写截断剧情或空响应。
