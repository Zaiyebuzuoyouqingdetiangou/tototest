- 副 API兔子镜的维修兔只维修当前镜面 DOM，绝不读取或重绘聊天正文。

## beta.14.48-test 本轮修复

- **挨打猫重说真正绑定当前副 API 兔子镜**：外置宿主和 `<details>` 同时保存聊天、消息、Swipe、记录 key 与正文指纹；挨打猫优先调用当前运行时的直连动作桥，事件委托仅作为回退。纯外置、外置后内嵌、旧缓存迁移后的宿主均可定位。
- **统一独立生成入口**：正文和可用思维链共同形成来源指纹；生成状态结束后还需连续稳定 2.8 秒才启动副 API。短回复也会生成，不再以 12 字为门槛。
- **真实取消旧请求**：正文重说、Swipe、聊天切换、生成方式切换、API 设置变化、插件停用或热更新时使用 `AbortController` 中止旧请求。旧结果无法回写新正文。
- **单任务、单宿主**：同一聊天、消息、Swipe、正文版本只允许一个轮询、一个网络任务和一个宿主。显示模式切换只移动同一 DOM；新加入的旧版重复宿主也会触发合并。
- **防止“打开后变成一条直线”**：移除对所有标题栏强制 `display:list-item` 和固定最小高度的全局样式；只在结构确实损坏或布局稳定后仍塌陷时，使用已保存的完整 HTML 重建当前宿主。
- **维修兔可返回修复前**：修复前保存原始 DOM 节点而不是只保存 `innerHTML`，返回时换回原节点，尽量保留原交互监听与运行状态；快照按聊天、消息、Swipe／外置 key 隔离。
- **本地存储限额**：当前结果和历史按 UTF-8 实际字节裁剪，优先保留最新内容；写入接近浏览器容量上限时自动淘汰最旧记录。
- **监听器完整清理**：独立 API、输出整理器和视觉扫描器在停用、清理与热更新时移除宿主事件、定时器和观察器；异步重新配置使用序列锁，避免重复安装监听。
- **副 API 兼容与上下文收口**：增加“不发送 temperature、但保留最大输出”的参数档；最近对话、角色、Persona、世界书和作者注释按总字符预算裁剪。
- **失败卡片保持精简**：失败状态只显示失败原因；原先无效的“重新生成／检测 API”卡片按钮及相关运行逻辑已删除。设置页中的模型列表和连接测试仍保留。
- **外框保持 beta.14.34 原始样式**：不读取兔子镜背景色，不做整框染色；旧自动取色属性只在迁移时清理。

## 安装

1. 在 SillyTavern 扩展管理中安装本版本 ZIP。
2. 覆盖旧版后彻底关闭当前酒馆标签页，再重新打开。
3. 打开 RabbitMirror 设置，确认生成方式、独立 API 地址、模型和显示方式。

更新前建议备份当前插件目录。卸载时删除 RabbitMirror 扩展目录；本地设置可在插件设置中重置。

## 生成方式

### 跟随当前 API

RabbitMirror Prompt 使用主 API 生成。可选择正文内显示或外置显示。跟随模式不使用独立 API 的“重说／兔子镜历史”。

### 使用独立 API

主 API 只生成正文；正文与可用思维链稳定后，RabbitMirror 通过 SillyTavern 自带的 Custom Chat Completions 后端请求所配置的兼容 API。无需额外 Server Plugin，也不由浏览器直接跨域访问目标 API。

独立显示方式：

- **① 纯外置**：生成中、成功和失败始终位于消息后的外置宿主。
- **② 外置后内嵌**：生成中和失败外置；成功后将同一宿主移动到正文后的专属 sibling anchor。不会复制第二份，也不写入 `.mes_text`、`mes` 或 `display_text`。

## 挨打猫

- 美化反馈可多选，并选择影响下一轮、3 轮或 10 轮；只有实际提交反馈时才会注入相应 Prompt。
- 独立 API 兔子镜的挨打猫菜单提供 `↻ 重说` 与 `◷ 兔子镜历史`。
- 重说只重生成当前消息、当前 Swipe 的兔子镜，不重说正文；当前版本会先保存进历史。
- 历史按聊天、消息与 Swipe 隔离，预览不会替换当前兔子镜。

## 维修兔 v2.09-test

- 只修模型已经输出的 HTML、CSS 与现有交互结构，不凭空补写剧情、答案或结果。
- 可处理无 label 控件、宿主丢失状态程序、触屏 Hover、局部 ID／radio 串联、3D 翻面等高置信问题。
- “返回修复前”只恢复当前兔子镜，不修改正文、Swipe 或其他消息。
- 自动巡逻默认关闭；开启后仅对之后新生成或重说的兔子镜尝试一次高置信本地修复。
- 截断或空壳内容无法凭空恢复，只会显示原因并提示重生成。
- 全链路诊断可能包含当前兔子镜正文，公开反馈前请检查隐私。

## Token 与数据

- 主 API模式下，以设置页“本轮 RabbitMirror 注入”统计为准。
- 独立 API模式下，RabbitMirror Prompt 不注入主 API；独立 API会单独消耗请求 Token。
- 维修兔、诊断、本地随机避重、模式迁移、历史预览和返回修复前不增加模型 Token。
- 挨打猫只有提交美化反馈后，才影响后续 RabbitMirror Prompt。
- 设置、抽取冷却、当前独立兔子镜和历史保存在浏览器本地；扩展不包含遥测，也不主动向开发者上传聊天内容。

## 已知限制

- 不同 SillyTavern 版本、浏览器、模型和其他扩展组合仍可能造成差异。
- 静态检查与模拟状态测试不能代替真实 iPhone Safari／WebView 的端到端验证。
- 本地存储容量由浏览器决定；极长兔子镜可能触发最旧历史自动淘汰。
- Token 数量是跨模型估算，字符数才是精确值。
